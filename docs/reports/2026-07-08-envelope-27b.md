## How the two weak families were fixed (all harness, no model changes)

The first envelope run scored find-and-report 10/20 and rename-refactor
9/20. Trace-level attribution found four harness defects, each fixed with
a test reproducing the failing trace:

1. **Inspect word-trigger** — "read" in a task prompt made prose answers
   illegal session-wide; the give-up contract then replaced correct answers
   with honest failures. Intent now binds only for ≤64-char imperatives.
   (find-and-report 10/20 → 20/20)
2. **Verification classifier** — `python3 report.py`, the check the task
   itself mandates, classified "unknown" and was preflight-denied in verify
   state, blocking the verify→see-failure→re-edit loop. Interpreters
   running a project file now classify as `verify`.
3. **Per-edit verify gate** — verify state bound after every single edit,
   so a multi-spot rename could never finish; the third Edit of the
   change-set was denied. Verify now binds at
   `pipeline.unverified_edit_limit` (default 6) unverified edits; Bash
   joined `edit_existing`; the done-claim gate still demands verification
   for any unverified edit. (rename-refactor 9/20 → 20/20)
4. **String scalars** — `replace_all: "false"` made otherwise-correct Edits
   schema-invalid; repair now coerces string booleans/numbers.

## Meta-finding

Across ~480 eval trials in this campaign, **no failure was attributed to
model intelligence**. Every failing family decomposed into a harness gate
fighting legitimate model behavior, and the recurring bug shape is
free-text intent detection applied to long task briefs. June's
"rename-refactor is a known weak task" belief was a harness artifact.
Corollary: word-trigger heuristics on prompts should be treated as guilty
until eval-proven, per umbrella principle 1.

## Envelope limits (what "supported" does NOT yet claim)

- Seven synthetic families ≠ the user's real workload distribution; the
  growth loop's trace corpus is the path to real-distribution families.
- Single-session tasks ≤300 s; long multi-hour sessions untested.
- `full` config with harness-owned policy; the agentic-os passthrough mode
  is unmeasured by this suite.
- One backend (27B int4). Config changes (quant, vLLM version) re-enter
  through this same gate.
